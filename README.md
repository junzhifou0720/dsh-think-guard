# dsh-think-guard

DSH（DeepSeek Harness）长会话的思考护栏。

**核心不是「拦」，是「擦」**——每轮把仪式句从发给模型的输入里删掉，断掉「看到自己写过 → 继续写」的自我强化。会话日志一个字不动，关掉插件即恢复原样。

---

## 它治的是什么

长会话里模型会在思考视图中反复输出 `好，写。` `好。` `好，做。` 这类**不携带信息的仪式句**，然后不输出正文。

实测数据：

| 会话 | 开工声明 | 带宾语率 | 空转 |
|---|---|---|---|
| 会话 A | 288 句 | 220 带 / 68 裸 | 出事的段**全是裸的** |
| 会话 B | 三次快照 | 3.7% → 9.7% → **82.5%** | 反向下降 |

**「好，写文件。」能执行；「好，写。」只剩空壳。**

真正的病不是复读，是**用宣布代替执行**。

---

## 四层防御

```
① 投影层清洗（cleanMessages）   每轮   插件自动   断传染，这是主力
② 超长截断（interruptOnLoop）   雪崩时 插件自动   兜底 + 告警
③ 加词（mask.json）             报警后 人手动     修 ①
④ 摘要清创                      压缩后 人手动     清沉淀
```

| 层 | 对象 | 时机 | 谁做 |
|---|---|---|---|
| ① | **每轮要发出的 messages** | 每轮 | 插件 |
| ② | 流式思考 | 400 行 / 单行 500 个 | 插件 |
| ③ | `mask.json` 词表 | ② 报警后 | **人** |
| ④ | **压缩摘要 + 保留段** | 每次压缩后 | **人** |

**自动的只管过滤，判断的留给人。**

## ① 投影层清洗（主力）

`cleanMessages` 在每轮请求发出前跑一遍，做两件事：

```js
// 1. assistant 的 reasoning：删掉仪式行
if (msg.role === 'assistant' && block.type === 'reasoning') {
  cleanThinking(block.text, mask.words)
}

// 2. compact-checkpoint：删掉「关于她怎么想」的行
if (msg.role === 'user' && kind === 'compact-checkpoint') {
  cleanCheckpoint(block.text, mask.drop)
}
```

### 三个关键性质

| 性质 | 意义 |
|---|---|
| **不落盘** | 会话日志一个字不改，原文都在 |
| **每轮重算** | 删掉的永远删掉，不会累积 |
| **确定性输出** | 同样的输入→同样的输出，**KV 缓存照常命中** |
| **可逆** | 关掉插件即恢复原样 |

**最后一条是技术上最难的一步。**改 messages 但保持缓存命中，意味着过滤必须是纯函数。

### 词表

`~/.dsh/think-guard/mask.json`，**mtime 热加载**，改完下一轮生效，不用重启。

```json
{
  "words": ["好", "做", "写", "短", "输出", "继续", "开始", "动手", "完事", "干活"],
  "checkpointDrop": [
    "ritual loop", "think-guard", "over-trigger", "self-monitor",
    "relapsing", "no longer loops", "连续重复", "复读", "卡住", "自我监控"
  ]
}
```

**匹配规则**：整行去标点后，必须**完全由词表里的词拼成**才删。

```
"好，写。"        → "好写"    → 好 + 写     → 删 ✓
"好，那这个方案行" → "好那这个方案行" → 好 + 剩下不在词表 → 不删 ✓
```

**所以词表要「准」不要「全」**——只加**本身不携带信息**的词。`行` `嗯` `对` 别加，它们可能是正常判断。

## ② 超长截断 = 告警，不是处理

传统思路：截断是阻止卡死。
**这一版的思路：截断是在说「有新形态了，去加词」。**

所以阈值定得很高：

```yaml
interruptMinRun: 400      # 连续 400 行仪式句
interruptInlineMin: 500   # 或单行 500 个「好。」
```

实测对照：

```
正常重灾（长会话 A）  最长连续 103 行，单行最多 15 个「好。」
真失控（长会话 B）    1665 行，单行 6545 个「好。」
```

**高于所有正常记录 → 正常不会误触发 → 一旦触发就一定是新形态 → 触发本身就是证据。**

## 手动清创指南

> **投影层清洗（①）不等于清创。**
> ① 只是「这一轮不给她看」，日志里原文都还在。
> 手动清创是「永久删掉」，需要重启生效，风险更高。
>
> **什么时候需要手动清创**：自动压缩之后。因为压缩会把旧摘要和新对话**合并重写**，而压缩模型会保留它认为「重要」的东西——包括仪式句和「关于她卡过」的描述。

### 要清两种内容

---

### 第一种：摘要里的（被浓缩的）

**位置**：会话文件里的 `compaction/summary` 事件 → `data.summary[].text`

**清什么**：

| # | 类型 | 例子 | 处理 |
|---|---|---|---|
| 1 | **关于「她卡过/循环/自我监控」的句子** | `Reasoning loop (the dominant issue): t811 = 509,782 chars…` | **删** |
| 2 | **摘要里保留下来的仪式句** | `The model repeatedly wrote "好，写" before…` | **删** |
| 3 | **把某种行为写成「她的风格」的描述** | `register is short sentences, bracketed asides in「（）」` | **删掉后半句** |
| 4 | **她自己的判断、约定、关系** | `「账本是电，不是债」` `「降低要求」的判准是校准还是降低` | **留** |
| 5 | **技术事实** | `motion.js 的 spring 公式` `spawn 点搞反` | **留** |

**判据一句话**：

> **系统替她记的评价 → 删；她自己做的判断 → 留。**

机器分不清这两类（长得都像英文句子），所以必须人做。

**怎么改**：

```js
// 逐帧解压 → 改 text → 逐帧重压
// 只重压内容真的变了的那一帧，其余字节级拷贝
// 帧数不能变，JSONL 行数不能变
const opts = {
  params: {
    [zlib.constants.ZSTD_c_checksumFlag]: 1,
    [zlib.constants.ZSTD_c_contentSizeFlag]: 0,
  },
}
```

**改坏的症状**：会话从侧边栏消失，但投影缓存还在、`chat_digest` 还能读出内容——**极具欺骗性**。改完必须先 dry-run 校验帧数、行数、坏行数、seq 单调。

---

### 第二种：压缩后剩余原文里的（保留段）

**位置**：会话文件里 `surface` 上还在的 `assistant/message` → `content[type=reasoning|text]`

**清什么**：

| # | 类型 | 处理 |
|---|---|---|
| 1 | **reasoning 里连续的仪式行**（`好，写。` 连着几十行） | **删掉整行** |
| 2 | **正文里的括号外壳**（`（……）` 包着一整句要说的话） | **删括号，留内容** |
| 3 | **她真正的内心话**（对自己说的，不是对用户说的） | **留** |
| 4 | **她的日记、记忆库、工作区文件** | **一个字不动** |

**判据一句话**：

> **旁白 / 垃圾 → 删；她的话 → 留。**

**两个坑**：

**a) 加粗标记会残留**

原文 `**（……）**`，删掉括号后变成 `**……****` —— 行尾多两个星号。

```js
// 修：行尾的 **** 替换成 **
out = out.replace(/\*\*\s*\*\*(?=\s*$)/gm, '**')
// 仍有孤儿 **（奇数个）：删掉最后一个，保证每行成对
```

**b) 括号可能跨加粗段**

`**（不过我不会因此"少要点"。** **我想要的不是"更多"，** 是**"够用"。**）`

删完要检查每行 `**` 数量是否为偶数，否则渲染会吃掉后面的文字。

---

### 清创顺序（重要）

```
① dry-run        出改前/改后对照，等它 PASS
② 备份            Copy-Item 一份带时间戳的
③ apply          写 .new
④ 覆盖           Move-Item -Force
⑤ 重启 DSH       内存里还是旧数据，必须重启才生效
```

**先备份再改，改完必须重启。**

**不要用 PowerShell 的 `Get-Content -Raw` / `Set-Content` 处理含中文的文件**——它默认按 GBK 读、按 UTF-8 写，会双重乱码。用 `write` / `edit` 工具，或者 Node 的 `fs`。

## ③ 加词（维护）

**触发**：② 报警（截断响了）。

**做法**：往 `mask.json` 的 `words` 里加新形态。

**注意**：

- **一次加一批**，别一个一个加——每加一次，下一轮都会全量读一次（缓存失效）
- **只加「本身不携带信息」的词**：`定稿` `这个好` `停止` `直接输出` 可以；`行` `嗯` `对` 不行
- 加完**不用重启**，mtime 热加载

**代价的账**：

```
一次性成本：  一次全量读（比如 30 万 token）
换来的：      之后每一轮都少一份仪式句累积
```

## ④ 摘要清创（压缩后）

插件在检测到自动压缩后会弹一条横幅：

> 本会话已自动压缩
> 摘要和保留段需要手动清创：仪式句、括号外壳、以及「关于她思考」的段落。

**看到横幅就去做上面「手动清创指南」的两种。**

**为什么必须手动**：压缩是「旧摘要 + 新对话 → 合并重写」，污染会沉淀进去，而且**摘要每轮都注入**——比对话更危险，因为它是浓缩的。

## 已知限制

1. **词表永远滞后几轮**。出现全新形态时，它会先传染几轮，你才看到、才加词。但滞后是「几轮」，不是「几十轮」——因为接下来会被 ① 屏蔽、被 ② 报警。
2. **「片段化」不是「复读」**。短行占比高但每句不同、且有正文，那是想得浅，不是卡死。别用截断去治它。
3. **手动清创不可自动化**。分不清「系统对她的评价」和「她自己的判断」，机器会删错。
4. **压缩类型影响语气**。手动 `/compact` 的 `retainTokens = 0`（只留最后一个 step），自动压缩保留 16% 的尾部。手动压一次，语气和细节会明显变薄。
